# Mario DDQN

A Double Deep Q-Network (DDQN) reinforcement learning agent, built from scratch in PyTorch, trained to play Super Mario Bros. via `gym-super-mario-bros` / `nes-py`.

## Project Structure

```
environment/            Environment construction and preprocessing
  mario_env.py             make_mario_env() - builds the wrapped Super Mario Bros env
  preprocessing.py         Grayscale/resize and frame-skip wrappers
  wrappers.py              Frame-stacking wrapper

agent/                  DDQN agent
  network.py               CNN Q-network
  ddqn_agent.py             Double DQN agent: action selection, learning step, checkpointing
  replay_buffer.py          Experience replay buffer
  exploration.py            Epsilon-greedy exploration schedule

training/               Training loop
  trainer.py                Episode loop, checkpointing, auto-resume from the latest checkpoint
  rewards.py                Reward clipping
  evaluation.py             Greedy-policy evaluation

main.py                 Entry point - starts or resumes training
play.py                 Loads a checkpoint and renders it playing live
test_mario_env.py       Minimal raw-environment sanity check / demo script

checkpoints/            Saved model weights (git-ignored; generated by training)
logs/                   Reserved for training logs (not yet used)
videos/                 Reserved for recorded gameplay (not yet used)
tests/                  Placeholder test files (not yet implemented)
config.yaml             Placeholder for centralized hyperparameters (not yet wired up)
requirements.txt        Python dependencies
```

## Requirements

- **Python 3.13** — required. `nes-py==9.0.1` (the Gymnasium-native build this project depends on) only ships wheels for 3.13; older Python versions resolve to a pre-Gymnasium `nes-py` with an incompatible API.
- A GPU is optional but strongly recommended — training on CPU is significantly slower.

## Setup

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
```

`requirements.txt` installs a CPU-only `torch` by default. For GPU acceleration, reinstall it with CUDA support afterward, matching your driver's CUDA version:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cu126 --force-reinstall
```

## Usage

**Train** — starts fresh, or automatically resumes from the newest checkpoint in `checkpoints/` if one exists (network weights, optimizer state, and the exploration schedule all resume correctly):

```bash
python main.py
```

**Watch a trained checkpoint play** — set `CHECKPOINT_PATH` in `play.py` to the checkpoint you want, then:

```bash
python play.py
```

## Known compatibility notes

`gym-super-mario-bros==7.4.0` has been unmaintained since 2022 and predates both NumPy 2.0 and Gymnasium. Two workarounds live in `environment/mario_env.py`:

- `SuperMarioBrosEnv._x_position` is monkey-patched to avoid a NumPy 2.0 scalar-overflow `OverflowError` (`ram[0x6d] * 0x100` fails because 256 itself doesn't fit in a `uint8`).
- The environment is built by instantiating `SuperMarioBrosEnv` directly instead of calling `gym_super_mario_bros.make()`, which is hardcoded to legacy `gym.make()` and rejects the Gymnasium-native spaces `nes-py` actually produces.

## Current status

The agent reliably clears World 1-1 and reaches partway into World 1-2 before dying, with training so far plateaued at a specific obstacle there. Training is fully resumable — just rerun `python main.py`.
